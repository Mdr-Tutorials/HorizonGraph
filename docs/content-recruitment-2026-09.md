# 2026-09-20 招聘与求职内容补充

本文记录首批内容及当时的验证结果。后续职业、量化、薪酬、职业发展和公司层级的补充见[职业、量化与公司内容续补](content-career-expansion-2026-09.md)；当前节点总数和检索验证以该续补记录为准。

新增 34 个数据词条，覆盖招聘与求职概念、四个平台、QR／QD 两个量化岗位、BAT 与 FLAG 两个企业合称，以及 LinkedIn 公司；已有岗位、力扣、系统设计面试与员工期权沿用原 id。

每个新词条包含中文摘要、正文、别名、分类、来源和至少一条非分类入边或出边。保留 `origin: ai_draft`，核对日期为 2026-09-20。资料以企业官方说明、产品文档和高校职业服务资料为主；社区记录只用于解释用词，不据此推广企业政策。

## 招聘入口与人才匹配（7）

- [校园招聘](../data/nodes/ca/campus-recruitment.json) — 面向应届毕业生等早期职业人群组织的招聘，通常按毕业届次设置申请范围。
- [社会招聘](../data/nodes/ex/experienced-hiring.json) — 面向社会人才按岗位需求开展的招聘，常结合相关工作经验评估职责匹配。
- [实习招聘](../data/nodes/in/internship-recruitment.json) — 为具有实践学习与阶段性工作安排的实习岗位选拔候选人的招聘活动。
- [员工内推](../data/nodes/em/employee-referral.json) — 由企业员工通过内部渠道向招聘团队推荐候选人的人才发现方式。
- [人员编制](../data/nodes/he/headcount.json) — 原指人数，招聘语境中常用于讨论规划或获批的人员编制与可招名额。
- [候选池](../data/nodes/ca/candidate-pool.json) — 为当前或未来岗位保留并组织候选资料的集合，可用于后续匹配与联系。
- [候选人重新匹配](../data/nodes/ca/candidate-rediscovery.json) — 根据新的岗位需求，从既有候选资料中重新查找、匹配并联系合适人选。

## 材料、经历与文书（7）

- [职位描述](../data/nodes/jo/job-description.json) — 说明岗位职责、任职要求及相关工作条件的招聘或组织管理文书。
- [简历](../data/nodes/re/resume.json) — 概括教育、经历与相关能力，供招聘方初步了解候选人的申请材料。
- [项目经历](../data/nodes/pr/project-experience.json) — 围绕具体项目记录问题、个人职责、实施过程与结果的实践经历。
- [作品集](../data/nodes/ca/career-portfolio.json) — 围绕求职目标组织作品、案例与说明，展示实际能力和个人贡献的材料集合。
- [开源贡献](../data/nodes/op/open-source-contribution.json) — 向开源项目提交代码、文档、测试、问题报告或其他协作成果的实践。
- [录用通知](../data/nodes/jo/job-offer.json) — 招聘方向候选人提出岗位及录用条件的通知，常以书面形式列明具体安排。
- [录用意向书](../data/nodes/em/employment-letter-of-intent.json) — 招聘方用于表达拟录用意向及后续安排的文书，具体内容随组织而异。

## 考核与准备（5）

- [在线笔试](../data/nodes/on/online-assessment.json) — 通过在线系统完成招聘题目或任务的评估环节，题型依岗位而定。
- [编程面试](../data/nodes/co/coding-interview.json) — 通过分析问题、编写代码和验证结果，考察候选人编程与解决问题能力的面试。
- [行为面试](../data/nodes/be/behavioral-interview.json) — 通过候选人的具体经历，了解其在协作、决策和问题处理中的行为方式。
- [STAR 方法](../data/nodes/st/star-method.json) — 按情境、任务、行动、结果组织经历叙述的方法，常用于行为面试准备。
- [HR 面试](../data/nodes/hr/hr-interview.json) — 由招聘或人力资源人员参与，了解经历、求职意愿及岗位匹配信息的面试沟通。

## 录用沟通与条件（6）

- [录用沟通电话](../data/nodes/of/offer-call.json) — 招聘方通过电话沟通录用意向、岗位待遇与后续安排的环节，常简称 OC。
- [Offer 审批](../data/nodes/of/offer-approval.json) — 组织在发出录用方案前，按内部规则核准相关条件的工作流程。
- [薪酬沟通](../data/nodes/sa/salary-negotiation.json) — 围绕岗位报酬组成、期望与可协商条件进行的信息确认和讨论。
- [入职意向确认](../data/nodes/em/employment-intent-confirmation.json) — 招聘双方核对加入意愿、岗位偏好与可开始时间等信息的沟通。
- [职级](../data/nodes/jo/job-level.json) — 组织按职责范围、工作复杂度与影响程度划分岗位层次的体系。
- [薪酬包](../data/nodes/to/total-compensation.json) — 对岗位现金、可变薪酬及权益等报酬组成的合称，具体口径需明确。

## 招聘平台（4）

- [牛客](../data/nodes/no/nowcoder.json) — 提供题库练习、求职交流、职位信息及企业笔面试服务的招聘平台。
- [BOSS直聘](../data/nodes/bo/boss-zhipin.json) — 以职位推荐和求职者与招聘方直接沟通为主要方式的在线招聘产品。
- [猎聘](../data/nodes/li/liepin.json) — 连接求职者、企业招聘方与猎头，提供职位信息和人才匹配服务的平台。
- [LinkedIn](../data/nodes/li/linkedin.json) — 连接职业人群、组织与工作机会的职业社交平台，支持职业资料展示和招聘。

## 量化岗位（2）

- [量化研究员（QR）](../data/nodes/qu/quantitative-researcher.json) — 运用统计、建模与编程分析数据，提出并验证投资或交易研究假设的岗位。
- [量化开发工程师（QD）](../data/nodes/qu/quantitative-developer.json) — 为量化研究与交易开发工具、数据管线及系统，推进研究成果的工程实现。

两者同时归入职业发展与量化金融领域，挂载职业岗位分类。JD 描述两种岗位；QR 连接机器学习、Python 和限定于 Jane Street 场景的 OCaml，QD 连接 Python、C++、ETL 与 CI/CD。正文根据 Citadel、Citadel Securities 与 Jane Street 的官方岗位资料说明职责重叠与技术选择边界。

## 企业合称与成员公司（3）

- [BAT（字节、阿里、腾讯）](../data/nodes/ba/bat-bytedance-alibaba-tencent.json) — BAT 的一种用法，指字节跳动、阿里巴巴与腾讯三家互联网企业。
- [FLAG（科技公司合称）](../data/nodes/fl/flag-facebook-linkedin-amazon-google.json) — 求职语境中的四家公司合称，F 沿用现名 Meta 的公司旧名。
- [领英公司](../data/nodes/li/linkedin-company.json) — 提供 LinkedIn 职业社交平台及相关商业服务的公司。

采用用户指定的 ByteDance、Alibaba、Tencent 释义，使用限定 id 与显示名，并通过 refers_to 指向三家已有公司。正文区分传统 Baidu、Alibaba、Tencent 释义；社区来源仅用于证明这种用法存在，不宣称行业已经统一更改定义。

FLAG 沿用 Facebook、LinkedIn、Amazon、Google 的展开，F 通过 refers_to 连接 meta，说明 Facebook 公司于 2021-10-28 宣布采用 Meta 名称。保留简称的历史拼写与同一公司的节点身份，依据 Meta 官方公告区分公司更名和 Facebook 产品名称。现有 Meta 节点改用 Meta 主名、原 Facebook 公司副名，保留原别名并补充更名正文；新编辑内容标记为 ai_draft。

既有 linkedin 是平台产品，新增 linkedin-company 表示公司，FLAG 的 L 指向公司，公司通过 provides 连接平台。公司与平台可在同一次 LinkedIn 搜索中出现，名称与类型明确区分，原平台 id 和内容保留。

## 别名与边界

- OC／HC／JD／STAR／QR／QD／BAT／FLAG 同时登记 abbreviation，保留中文与英文检索入口。
- 修复搜索中前缀累加分数压过完整缩写的问题：名称、缩写、别名或 id 完整匹配优先。例如 OC 排在前缀匹配的 OCaml 之前。
- JD 同时命中原有京东节点与职位描述；保留同名实体，不用招聘含义覆盖公司含义。
- “HR面”命中 HR 面试；“捞人”“被捞”命中候选人重新匹配；“泡池子”命中候选池。
- “开奖”同时作为 OC 与薪酬沟通的检索别名，正文各自解释语境，不作为独立标准流程。
- “意向书”限定为录用意向书，使用 employment-letter-of-intent；“作品集”使用 career-portfolio。
- 薪酬包使用 total-compensation，保留已有 compensation（肌肉代偿）的身份和内容。
- 实习招聘描述选拔活动，不把实习工作经历本身登记成同义词。
- 录用意向、OC、书面通知、内部审批与接受决定分别说明，不推导统一顺序、时长或法律后果。
- 意向书来源中的历史校招案例标明年份，不代表该公司当前流程。

## 分类与关系

新增“职业与招聘”及其四个子分类：职业岗位、招聘流程与方法、招聘材料与经历、录用条件与编制；另在产品下新增招聘平台，共 6 个导航节点。

12 个岗位从直接挂载“理论”改为其后代“职业岗位”；系统设计面试与员工期权挂到更具体的分类。前端、后端、全栈、算法与数据工程师补充正文及实际工作中的技术使用关系。旧 id 和原有非分类关系保留。

QR 和 QD 加入后，职业岗位分类共 14 个词条。BAT 与 FLAG 是职业与行业讨论中的称谓概念，挂载“职业与招聘”；LinkedIn 公司挂载组织分类。

关系语义见 [ADR-0022](decisions/0022-recruitment-context-relations.md)：

- assesses：评估活动考察的知识或方法，例如编程面试考察复杂度分析。
- prepares_for：资源或方法用于准备评估，例如力扣用于准备编程面试。
- describes：材料描述的内容，例如简历描述项目经历，JD 描述岗位。
- discusses：沟通活动涉及的议题，例如 OC 沟通薪酬包。

企业合称另使用 [ADR-0023](decisions/0023-organization-appellation-relation.md) 中的 refers_to（指代／相关称谓），仅允许概念指向组织并明确释义；不推导组织隶属或共同招聘。

这些关系及原有 uses、stewarded_by 通过契约的 requires_context 声明上下文要求，校验器统一检查非空字符串；正反向中文标签进入前端邻域排序，反向边仍由构建派生。

连通路径包括 JD／岗位／日常技术；简历／项目经历／行为面试／STAR；力扣／编程面试／数据结构；社会招聘／系统设计面试／架构取舍；OC／薪酬包／员工期权；Offer 审批／HC；候选人重新匹配／候选池；JD／QR 或 QD／Python；BAT／字节跳动、阿里巴巴或腾讯；FLAG／Meta；FLAG／LinkedIn 公司／LinkedIn 平台。

岗位技术关系是按具体场景整理的编辑性概括，正文附对应资料。可选技术、题型和薪酬组成都在 context 中限定。
