# ADR-0026：基础领域内容的分类与消歧

- 状态：已接受
- 日期：2026-10-01

## 背景

图谱已有较多语言、工具和产业实体，但数学统计、经典机器学习、系统机制、数据治理、应用安全、机器人控制、数字电路与人机交互的基础概念较薄。仅添加词条并泛挂 theory，会让这些领域缺少可探索的分类入口，也无法表达与已有工程实体的实际联系。

## 决策

1. 本体从 0.8.0 升至 0.9.0，新增数学基础、统计方法、机器学习方法、机器学习评估指标、操作系统机制、编译与运行时机制、数据工程概念、应用安全概念、机器人与控制方法、数字电路设计概念、交互设计概念和数据集十二个分类。概念分类继承 theory，评估指标继承 metric，数据集继承 product，不增加 EntityType。
2. domains 注册表从 0.2.0 升至 0.3.0，登记 mathematics、statistics、data-engineering、robotics、control-theory、digital-design、semiconductor-engineering。既有 10 个生态根与关系类型保持原契约；领域表示知识主题，本体表示实体是什么。
3. 数据集作为可交付的数据制品使用 product，与已有教材、课程、文档等资料制品采用同一实体类型。Product 的说明明确包括资料制品，不表示这些对象必然商业收费。理论性的网络结构仍可建 concept，真实软件实现或模型制品按其实际身份分类。
4. 保持已发布 id。统计方差使用 statistical-variance，与 variance 的类型变型释义分开；coco-dataset 与 cocos 分开；usability 与 availability 分开。缩写与别名允许同名，搜索层依据独立 id、摘要和类别消歧。
5. 新增与实质扩写内容标为 ai_draft，记录本次研究日期，在 description 中附主题对应的一手来源。正文解释机制、应用条件与边界，摘要保持在 50 字以内；不把公开文档或搜索结果等同于人工审校。
6. 关系仍遵循 ADR-0021 与单向存储契约：具体采用方法用带 context 的 uses，实际工程实现用 implements，硬软件依赖用 depends_on，官方互操作用 integrates_with。不建立“主题相关”边，也不把可选插件、传感器、训练框架推成所有部署的依赖。
7. 新词条需要在完整图谱中具有至少一条非分类连接，可由已有节点指入。增加正文与机制边，形成概念、实现、规范、学习资源及产业主体之间可遍历的路径。原有关系仅在分类细化或证据表明语义不成立时修正，并在批次说明中记录。

## 后果

这批内容可从分类与搜索进入，并通过既有工具和标准继续探索。分类扩展兼容现有实体类型、查询引擎和静态发布流程；数据快照、搜索索引、邻域、正文与离线资源需要随内容统一重建。批次清单与来源见 [2026-10 内容扩展](../content-foundations-2026-10.md)。
