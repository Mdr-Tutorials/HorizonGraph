# ADR-0010：分类骨架的平面归属与搜索降权

- 状态：已接受
- 日期：2026-08-29

## 背景

叶子/非叶子不是二值：`specializes` 允许中间分类节点存在（如 Transport Protocol，type 为 concept）。ADR-0004 只将 meta_concept 本体归入契约平面，中间分类节点归属未定，分类骨架会被劈成两半。另外分类节点名是通用词（"协议"、"Protocol"），与日常查询词正面相撞，同权重会污染搜索结果。

## 决策

1. 凡接收 `is_instance_of` / `specializes` 边的节点（即非叶子）一律属分类骨架，进契约平面本体文件；数据平面节点只向上发边、永远为叶子
2. 平面归属与拓扑角色严格对齐，CI 一条规则校验：数据平面文件被分类边指向即失败
3. **树是导航层，网是探索层**：分类骨架（树）承担导航与分类页；数据边（网）承担穿透与探索。两者同构渲染——同一模板，实例列表由派生反向边填充
4. 搜索降权分区：分类角色节点在检索层降权或以"导航"分区单独展示，与词条命中分开；通用词查询不得让元节点压过具象词条
5. 本体文件携带渲染所需字段（id / name / summary / aliases），分类页渲染数据由 build 从本体文件加派生反向边生成
6. 本体改动随数据 PR 同一通道提交（见 ADR-0013 单一贡献通道），无额外审批分层

## 后果

正面：分类骨架单源；CI 单规则可校验；搜索不被通用词污染。
负面：分类节点变更触及契约文件，贡献者需理解本体文件结构——由贡献文档与 CI 报错信息补偿。
