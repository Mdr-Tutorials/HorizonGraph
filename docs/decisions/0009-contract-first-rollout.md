# ADR-0009：先契约后数据——试点、冻结、铺量

- 状态：已接受
- 日期：2026-08-29

## 背景

所有破坏性变更的成本与存量数据成正比。当前数据量为零，是唯一的免费窗口。

## 决策

1. 顺序铁律：**契约先于数据**。types.json、relations.json、vocab/、CI 校验器先落地，Schema 修订随后，最后铺数据
2. 试点批次：50–100 个节点，刻意覆盖全部 realm 与全部关系类型（建议样本：C++ Concepts、GLM、CNCF、QUIC、NVIDIA H100、FPS 等），集中暴露缺词与选边分歧
3. 评审冻结：依据试点修订关系枚举（0003）与词表（0004），契约打 v3.1 标签
4. 铺量阶段：词表走 lockfile 流程（0004），契约变更需显式 PR 并修订对应 ADR

明确拒绝的反模式：先铺数据后补规则——类型错误会固化进存量，三个月后 Schema 被一千个节点绑架。

## 后果

正面：结构性风险在零成本窗口内解决；试点为契约修订提供实证依据。
负面：铺量启动时间后移约一个试点周期；试点批次本身可能被大幅返工——可接受，试点的目的就是返工。
