# ADR-0028：实时图形、交互内容与资产工程

- 状态：已接受
- 日期：2026-10-07

## 背景

前两批内容扩展补充了基础知识和十二个应用领域，但 PixiJS 缺失揭示了另一条未覆盖的工程主线。扩展前 graphics 与 game-development 标签的去重集合有 63 个节点，其中只有 3 个存在正文；绘图 API、游戏引擎与图表库已有入口，场景、逐帧运行、动画制作、资产交换与交互探索尚未连通。

## 决策

1. 同批补齐六个相互连接的分支：浏览器二维图形与交互画布、实时渲染机制、游戏与互动运行时、创意编程与动画、数字内容制作与资产管线、交互可视化与 Web 地理空间。新节点和既有扩写均解释实际机制、适用范围与工程连接；完整范围记录于批次文档。
2. ontology 从 0.10.0 升至 0.11.0，增加六个继承 theory 的概念分类，以及继承 protocol 的 api-specification 和 graphics-asset-format，合计 78 个本体节点。FPS、帧耗时等性能指标仍归 metric；语言、库、工具、产品与格式各按真实身份挂载。
3. domains 从 0.4.0 升至 0.5.0，登记交互图形、实时渲染、创意编程、计算机动画、数字内容创作和数据可视化六个领域标识，合计 59 个。游戏开发与地理空间使用既有标识，交叉归属按节点内容声明。
4. ecosystems 从 0.2.0 升至 0.3.0，登记七个子生态，合计 82 个。既有十个宏观生态根维持封闭；二维图形与创意编程连接图形和 Web，实时渲染连接图形与硬件，Web 地理空间连接地理空间与 Web。
5. schema_version 从 3.5.0 升至 3.5.1，仅对类型说明作文字对齐：protocol 包含接口规范与数据格式，tool 包含内容创作与分析工具，product 说明包含可交付资料，ai_draft 说明允许存根或完整正文。字段、枚举值和适用性不变；关系类型仍为二十九种。
6. 接口规范不分类为网络应用层协议。软件调用 Canvas/WebGL/WebGPU 使用 uses 并解释后端条件，不能将调用 API 写成实现 API。格式与加载器、动画编辑器与运行库分别建档；GLB 是 glTF 的二进制封装，与 GLBP 身份不同。
7. 保持既有 id。游戏场景与渲染场景图、图形合批与通用 batching、渲染几何与计算网格分别定义。同名品牌、格式与工具允许共享 aliases，以摘要、类型和 id 消歧。版本变化显著的功能使用来源支持的范围，不将历史 Phaser/Pixi 架构或实验后端推广到所有当前部署。
8. 每个新增节点都具有正文、对应的一手资料和至少一条非分类入边或出边。新增与实质扩写内容保留 ai_draft，研究日期为 2026-10-07；资料优先使用标准正文、官方概念指南、API 文档及项目仓库。
9. 契约验证、完整生产构建与既有测试覆盖本批；另外直接从实际构建产物读取全部新增/扩写的摘要、正文和邻域，检查全部新增 id 搜索及代表性品牌别名、规范名和同名消歧。离线发布清单随构建重生成，内容不绕过版本化数据管线。

## 后果

图谱可以从内容创作沿资产格式、场景对象、逐帧更新、动画、GPU 绘制与输入交互继续探索，也可以从数据与地理信息进入交互图表和地图客户端。类型说明与既有实际录入一致，扩展沿用现有搜索、邻域和离线引擎。

批次范围、完整节点清单、来源、关系修正与验证见 [实时图形与交互内容补全记录](../content-interactive-graphics-2026-10.md)。
