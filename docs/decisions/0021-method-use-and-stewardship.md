# ADR-0021：方法使用与项目治理关系

- 状态：已接受
- 日期：2026-09-12

## 背景

补齐基础算法、检索、AI 基础设施与标准组织时，需要表达 BFS 使用队列、SLO 使用 SLI、Apache 项目由基金会治理等事实。现有 depends_on 只表达工程工件间的直接硬依赖；governs 表达理论约束；developed_by 表达研发归属。用这些关系替代方法使用或机构治理，会错误扩大依赖、发明或维护责任。

## 决策

1. 新增 uses（使用 / 使用方）：源和目标均为非人物、非组织的数据词条。必须用 context 说明具体采用的方法、指标或能力；可选实现须限定场景。禁止把主题相近当作使用关系。
2. 硬软件依赖继续使用 depends_on；工程化实现使用 implements；官方组件互操作使用 integrates_with。uses 不替代更精确的既有关系，同一事实不重复存储。
3. 新增 stewarded_by（治理方 / 治理项目）：源为技术词条、概念、度量或组织，目标为组织。context 写明标准制修订、项目治理或正式基金会托管职责。仅赞助、普通会员或提供资金不能建立此边。
4. 两种关系均由使用方或被治理方存储规范方向，反向邻域由构建派生。校验器要求非空 context，并沿用域、值域、死边、自环与重复边校验。
5. relations.json 从 1.4.0 升至 1.5.0，新增两种关系；既有关系保持兼容。前端邻域顺序加入对应正反向中文标签。

## 后果

算法与指标可以建立有明确场景的联系；标准组织和基金会可以与项目相连，而不被误记为原始研发者。新增词条按实际来源保留 ai_draft，附权威资料供后续人工审校。
