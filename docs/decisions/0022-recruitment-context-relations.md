# ADR-0022：招聘语境中的评估、准备、描述与沟通关系

- 状态：已接受
- 日期：2026-09-20

## 背景

招聘节点需要表达面试考察知识、力扣用于准备面试、简历描述经历，以及 OC 沟通薪酬。现有 uses 表达方法或能力使用，无法准确承载全部场景；文书所描述的对象也不因此成为其组成部分。

## 决策

1. 新增 assesses（考察／考察场景）：评估活动指向所考察的数据概念或度量，context 说明能力、题型或岗位场景；不评价具体个人。
2. 新增 prepares_for（用于准备／准备资源）：概念、产品或工具指向评估活动，说明准备内容，不推导招聘方采用某平台或保证通过。
3. 新增 describes（描述／描述于）：文书、材料或记录指向其描述的概念或度量，不推导组成、真实性背书或当前职位空缺。
4. 新增 discusses（沟通内容／沟通场景）：沟通活动指向议题，不推导流程先后、审批结果或达成一致。
5. 四种关系均单向存储，指向数据词条，由构建生成反向视图；保留 uses 等原有关系的语义。
6. 关系契约增加 requires_context。uses、stewarded_by 和四种新关系声明为 true；数据边和本体叙事边都检查非空字符串。
7. relations.json 从 1.5.0 升至 1.6.0；ontology.json 从 0.6.0 升至 0.7.0，新增 6 个分类。现有岗位等只调整数据中的分类挂载，旧 id 与非分类边保留。
8. 招聘平台作为 product，挂载招聘平台分类，使用已有企业应用生态；职业概念沿用 career-development 领域，不增加宏观生态根。
9. OC、HC、JD、STAR 放入 abbreviation；捞人、开奖等进入别名与正文。“开奖”允许返回两个相关词条，不创建缺少稳定定义的流程节点。

## 后果

用户可从岗位、技术、材料和招聘术语双向浏览。关系必须附具体场景，避免把常见做法写成普遍要求。历史案例与社区用语标明来源性质，文书和电话节点不承担跨地区法律效力判断。

## 验证要求

全量 pnpm build；检查新词条与短缩写的实际前端搜索、L2 正文及双向关系；用隔离输入验证新关系上下文、类型和目标限制；与修改前快照比较旧节点身份与非分类边。
