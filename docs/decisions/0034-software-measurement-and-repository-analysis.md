# ADR-0034：软件度量、仓库分析与质量验证

- 状态：已接受
- 日期：2026-10-08

## 背景

对完成 Tern/Ghostty 批次后的 3027 个数据节点检索 ID、名称、缩写、别名及正文，没有发现 scc 或 tokei。已有静态分析、Git 与测试条目，但源码计数、结构度量、仓库演化、克隆与技术债、覆盖与变异测试、实证研究和工程度量解释缺少连续的知识路径。

本批分别收录具体计数工具，沿相关方法、指标、分析器与研究资料补充缺口。范围、完整节点清单、来源与最终验证写入 [内容批次记录](../content-scc-tokei-and-software-measurement-2026-10.md)。

## 决策

1. 本体 101 → 107，版本 0.17.0。新增 software-measurement-concept、repository-analysis-concept、software-quality-concept、software-testing-concept、empirical-software-engineering-concept，继承 theory；software-engineering-metric 继承 metric。具体工具、库、产品、文档和数据集继续按既有分类挂载。
2. 领域 79 → 84，版本 0.11.0。新增 software-measurement、repository-analysis、software-quality、software-testing、empirical-software-engineering；编译器、语言工具链、安全、命令行等交叉领域按实际内容复用。
3. 生态 101 → 106，版本 0.9.0。软件度量和实证软件工程归入工程工具链；仓库分析同时接入 Git 生态；质量与测试继承已有静态分析和测试生态。宏观生态根保持十个，不因同一内容批次让所有节点加入全部生态。
4. Schema 保持 3.5.1，关系种类保持二十九种。保留既有 ID，并扩写相关旧节点；估算方法作为 concept，度量结果定义作为 metric，运行工具、嵌入库与托管平台按实际工件身份分别表达。普通软件成本模型不归入 AI 模型族。
5. 工具使用方法和指标采用 uses，并在 context 限定实现、配置或计算口径；公式输入可以由指标持有 uses。被测对象不会因被测量而反向使用指标。定义相似、共享名称和研究相关性不能充当硬依赖、组成或因果关系。

## 源码计数与结构度量

物理行、逻辑行、代码行、注释行、空行和文件数分别定义；语言识别、嵌入语言、生成文件、供应商代码、重复文件及忽略规则影响统计对象和分母。工具默认值与用户设置须分别说明；同一名称的指标不能据此假定所有实现口径相同。[NIST：软件产品测量量与单位](https://nvlpubs.nist.gov/nistpubs/ir/2020/NIST.IR.8289.pdf)

scc 的词法复杂度估计与基于控制流图的圈复杂度分开。DRYness 和唯一行统计不能替代语义克隆检测；COCOMO 和 LOCOMO 的模型假设与估算结果不能视为实际成本账单、项目承诺或个人生产力。[scc 官方项目](https://github.com/boyter/scc)

tokei 的语言和文件统计、嵌入内容处理、历史统计输入以及导出格式按具体实现说明。输入已有统计的累加行为不写成自动差分或去重；构建特性、当前源码与发行版本分别限定。[tokei 官方项目](https://github.com/XAMPPRocky/tokei)

复杂度、Halstead、可维护性和面向对象指标保留公式及实现差异。功能规模、源码规模、相对估算与工时单位分别记录，不给出跨语言、跨团队通用换算，也不把高低数值直接写成质量结论。

## 仓库分析与质量验证

仓库语言份额不等同源码行数。Git 作者与提交者、历史贡献与声明责任、浅克隆与完整历史、重命名启发式与真实文件身份分别说明；churn、hotspot、ownership、SZZ 和时间耦合是有采样及建模条件的分析，不能仅凭版本历史推出缺陷原因或个人能力。

质量平台、扫描器、质量门、规则配置与新代码范围分别建档。技术债、代码异味、克隆与检测规则具有不同含义；工具估算的修复时间或阈值不能视为所有项目统一的真实工作量。产品代际、发行状态、可选能力与版本条件按一手资料限定。

覆盖指标注明被覆盖对象和分母，语句、行、分支、条件、路径与 MC/DC 不互相替代。插桩和排除规则会改变数据；变异测试分别说明检出、存活、等价、错误与超时。覆盖率或变异分数不构成业务正确性和整体测试质量证明。

## 度量解释与实证研究

软件度量从信息需要出发，记录对象、方法、单位、采集与解释条件。构念效度、可靠性、研究内部和外部效度及统计结论分别表达；观察研究、实验、案例、调查、重复研究与基准都有各自适用范围。[SEI：建立软件测量过程](https://www.sei.cmu.edu/library/establishing-a-software-measurement-process/)

DORA 使用复核时的官方指标定义和作用域，SPACE 与 DevEx 按多维框架说明；源码行数、提交数、活动量及交付指标均不能不经背景解释直接转化为个人绩效。性能基准明确工作负载、环境、缓存、预热和统计方法，工具作者的某次对比不推广为通用速度排名。

## 结果

scc 和 tokei 可以沿代码规模、结构指标、仓库分析、质量与测试及度量解释继续探索。新增和扩写节点保留 ai_draft 与 2026-10-08 复核日期；独立内容复核、全量契约校验、生产构建、JS/WASM 检索及离线浏览器检查结果写入内容批次记录。
