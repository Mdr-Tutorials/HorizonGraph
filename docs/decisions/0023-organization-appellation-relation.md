# ADR-0023：企业合称的指代关系

- 状态：已接受
- 日期：2026-09-20

## 背景

BAT 的 ByteDance、Alibaba、Tencent 释义需要连接图谱中已有的三家公司。合称本身是概念，既不是新的企业，也不意味着这些公司构成一个共同组织。既有 composed_of 和 part_of 表达组成关系，不能准确承载这一语义。

## 决策

1. 新增 refers_to（指代／相关称谓），仅允许 concept 指向 organization，称谓一侧存储，由构建派生反向视图。
2. requires_context 为 true，明确具体释义及所指对象；沿用通用上下文与类型校验，不新增例外分支。
3. 多义缩写采用限定 id 和显示名。bat-bytedance-alibaba-tencent 指代字节跳动、阿里巴巴、腾讯，正文区分传统 Baidu、Alibaba、Tencent 释义；不把百度作为第四个成员混入同一释义。
4. 单个组织的别名仍登记在 aliases，生态圈层仍使用 ecosystems；指代关系不表达所有权、隶属、治理、研发、合作或当前招聘。
5. relations.json 从 1.6.0 升至 1.7.0。前端沿用契约中的正反向标签，将指代关系纳入已有邻域排序。
6. BAT 保留为 ai_draft，社区记录仅支持这种用法的存在，不用它推导行业统一定义或公司政策。
7. 组织更名与合称字母分开处理。FLAG 保留 Facebook、LinkedIn、Amazon、Google 的历史展开，F 指向原有 meta 节点；Meta 显示现名，旧公司名称保留为 aliases，正文说明 2021 年公司更名与 Facebook 产品名称的区别。不为同一公司另建旧名组织，不自动生成新的缩写。
8. 称谓中的成员是公司时必须指向组织。既有 linkedin 是职业社交平台产品，新增 linkedin-company，并通过 provides 连接平台；现有产品 id 保留。

## 后果

用户可从合称进入公司，也可从公司反向找到相关称谓。不同释义的所指对象明确分开，日后收录传统 BAT 等用法时不需要更改已有节点身份。

## 验证要求

全量构建；验证 BAT 的缩写与全称检索、L2 正文、三家公司正反向关系；隔离校验合法指代边、上下文缺失或类型错误、非法源与目标、本体目标与死边。

FLAG 补充检查：四条指代关系均连接组织，F 指向 meta，L 指向 linkedin-company；Facebook 和 Meta 搜索命中同一公司，LinkedIn 搜索同时保留公司与平台，原有 Meta 入边及其他已有数据不因更名丢失。
