# ADR-0001：三平面架构——数据、契约、派生分离

- 状态：已接受
- 日期：2026-08-29

## 背景

TechTermSchema v3.0 评审将 11 个问题收敛为 3 个根因：EntityType 一肩三职、关系语义仅存于注释、缺治理层。逐项打补丁会延续结构病。本项目为静态优先架构（GitHub Pages JSON 矩阵），节点体积直接决定 CDN 成本与加载性能。

## 决策

仓库分三平面：

| 平面 | 内容 | 性质 |
|---|---|---|
| 数据平面 | TechTermSchema 节点 | 手写，唯一事实源 |
| 契约平面 | 类型注册表、关系规格表、受控词表、约定文档 | 手写，机器可读 |
| 派生平面 | 反向索引、1-hop 切片、搜索索引、词表快照、redirects | build 生成 |

铁律：**节点 = 事实，契约 = 规则，产物 = 视图。**

- 派生物永不手写、永不手改，全部由 build 生成
- 治理信息一律上移契约平面，节点保持最小体积

## 后果

正面：Schema 四维结构无需重构；节点文件不随规则增长膨胀；规则由 CI 强制执行而非依赖自觉。
负面：需一次性建设 build 派生管线与 CI 校验器；贡献者需理解"改数据"与"改契约"的边界。
中性：契约文件成为新的核心资产，需自身版本管理。

## 关联

0002、0003、0004 是契约平面的具体内容；0009 规定其落地顺序。
